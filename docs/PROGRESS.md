**2026-11-25 — Windows GPU transcription verified on real hardware; transcripts no longer carry invisible bidi control characters; two tests fixed for Windows (offline code + tests + docs; one-time model download, no paid API calls). ✅ DONE**
First real run of the Windows install and the NVIDIA GPU path. On Windows 11 Pro (10.0.26200), Python 3.13.7, RTX 4090: `py -3.13 install.py --gpu` installed faster-whisper 1.2.1, ctranslate2 4.9.1, nvidia-cublas-cu12 12.9.2.10 and nvidia-cudnn-cu12 9.28.1.4; `transcribe.py --capabilities` printed `{"diarization": false, "engine": "faster-whisper", ...}`. A 28 min 10 s Hebrew mp3 (`--lang he --json`) ran on `cuda (float16)` with `ivrit-ai/whisper-large-v3-ct2`, exit 0, 458 lines: 132.2 s on the first run including the 3.1 GB download, 97.7 s cached. That run surfaced two things. (1) 159 of 458 lines held U+202B (RLE), sometimes mid-line (`קבוצה ‫שאנחנו`), coming from the model's output, not from this project's code; `transcript_output.clean_text()` now strips all bidi controls at render time for plain, labelled and fallback text, and drops a segment that is only controls (decision row 1). Re-run on the same file: 458 lines, 0 bidi controls. (2) The unit suite was 167 passed / 2 failed / 1 skipped on Windows; both failures were test bugs, not product bugs: `test_a_real_cp1252_stream_can_print_hebrew_afterwards` got `\r\n` from a default `TextIOWrapper` on Windows, and `test_mac_still_unescapes_drag_and_drop` simulated macOS on a Windows temp path whose backslashes got unescaped away (decision row 2). Proof after the change: `.venv/Scripts/python -m unittest discover -s tests -t .` → `Ran 178 tests ... OK (skipped=1)` (the skip is the Mac-only setup.sh test).
