Same machine as the entry below (Windows 11, RTX 4090, i9-14900K with 32 logical cores, Python 3.13.7), same 28 min 10 s Hebrew mp3. `py -3.13 install.py --gpu --with-diarization` exit 0 in 7 m 43 s: torch 2.14.1+cu126, torchaudio 2.11.0+cu126, pyannote.audio 4.0.7; `torch.cuda.is_available()` True; `--capabilities` printed `"diarization": true`. The first `--speakers auto` run failed: `OSError: [WinError 127] The specified procedure could not be found. Error loading "...\torch\lib\cudnn_cnn64_9.dll"`. Cause: `CudaLibraryProbe` loaded cuDNN 9.28 from `nvidia-cudnn-cu12` for CTranslate2, then torch's bundled cuDNN 9.10.2 (same file names) bound to it. Reproduced in isolation (probe then `import torch` fails; torch then probe works). Fix: `candidate_library_folders()` lists `torch/lib` first (decision row 3). After the fix: `--speakers auto` exit 0, `Transcription running on: cuda (float16)`, `Diarization running on: cuda`, 590 turns, 5 speakers, 551 lines, 0 bidi controls; 122.8 s first run including the pyannote download, 118.5 s cached. Plain GPU re-run after the fix: 96.8 s, 458 lines (before: 97.7 s, 458), so no regression. CPU, forced with `CUDA_VISIBLE_DEVICES=-1`: `cpu (int8, 16 threads)`, `ivrit-ai/whisper-large-v3-turbo-ct2` (pre-fetched so the time excludes the download), 270.8 s, 437 lines, 6.2× realtime.
